# pal-harness 1.10.0: plan

**Design:** `doc/specs/2026-11-24-harness-1.10.0-design.md` (approved 2026-11-24).
**Branch:** `feature/harness-1.10.0` from `origin/dev` (the design, this plan and every change). One PR into `dev`.

## Summary

1. Tasks: `minors` (1), `merge-check` (2), `spec new` from `origin/dev` (3), the rule tests and text
   (4–5), the release files (6), the full check and the PR (7).
2. Repo: pal-harness only. No project's pin changes.
3. Approach: inline. One repo, three small Go changes and rule text.
4. Proof: `go vet ./...` and `go test ./...` (what `ci.yml` runs), with `go test -coverprofile` holding
   the 80% gate. Local runs set `GOFLAGS=-p=1 GOMEMLIMIT=2GiB`.
5. Every Go change is test first: each task commits its failing test, then the code. The rule text is
   pinned by `TestHarness1100Rules`, written red before the text. The version stays 1.9.0 until Task 6,
   so `TestCITemplateWiring` holds until then.
6. Risks:
   - `spec.md` (150 of 150) and `build.md` (149 of 150) are at their line caps, so their edits are
     rewrites in place.
   - `merge-check` uses a throwaway `git worktree`. It must always be removed, even after a failed
     merge, and the caller's tree must stay unchanged. The tests check both.
   - This PC has git 2.34, so nothing may use `git merge-tree --write-tree`.

## Tasks

#### Task 1: `pal-harness minors`

- Files: `cmd/pal-harness/minors_cmd.go`, `cmd/pal-harness/minors_cmd_test.go`, `cmd/pal-harness/main.go`
  (dispatch and usage), `README.md` (command row).
- Test first (`TestMinors*`, run red): a ledger with `Task N: minor (deferred) [carry|final|later|issue|fixed]: …`,
  an untagged `minor (deferred):` line, an unknown tag `[soon]`, a `Task N: parked — … — Ruling: …` line,
  bullet prefixes (`- `) and unrelated lines:
  - prints the groups in order carry, final, later, issue, parked, untagged, with counts, and `fixed (N)` as a count only;
  - exit 1 with an untagged or unknown tag, 0 when every minor is tagged;
  - `--tag carry` and `--task 3` filter, and still exit 1 on an untagged line in the filtered set only;
  - a missing file, no argument, a bad tag name or a non-number task is exit 2.
- Code: one regexp per line kind; groups printed as in the design.
- Prove it: `go test ./cmd/pal-harness/` and `go vet ./...` pass.
- Commits: `Pin pal-harness minors in failing tests`, then `Add pal-harness minors to list deferred minors by tag`.

#### Task 2: `pal-harness merge-check`

- Files: `cmd/pal-harness/merge_cmd.go`, `cmd/pal-harness/merge_cmd_test.go`, `cmd/pal-harness/main.go`,
  `README.md`.
- Test first (`TestMergeCheck*`, run red), using the test repo helpers with a bare origin:
  - clean: a branch and an `origin/dev` that touch different files → exit 0, `merge-check: clean against origin/dev`;
  - conflict: both change `doc/decisions.md` → exit 1, the path on its own line;
  - not a repo, or a failing fetch (a remote URL that doesn't exist) → exit 2;
  - `--base origin/main` is honoured;
  - after each case, the caller's `HEAD`, branch, `git status --porcelain` and `git worktree list` are as before.
- Code: `git fetch origin <branch>` (base `<remote>/<branch>`), `os.MkdirTemp`,
  `git worktree add --detach <tmp> HEAD`, `git -C <tmp> merge --no-commit --no-ff <base>`, conflicts from
  `git -C <tmp> diff --name-only --diff-filter=U`, a deferred `git worktree remove --force <tmp>` and
  `git worktree prune`.
- Prove it: `go test ./cmd/pal-harness/` and `go vet ./...` pass.
- Commits: `Pin pal-harness merge-check in failing tests`, then `Add pal-harness merge-check to find conflicts before CI`.

#### Task 3: `spec new` from `origin/dev`

- Files: `cmd/pal-harness/main.go` (`newSpec`), `cmd/pal-harness/main_test.go`, `README.md` (the spec row).
- Test first (run red):
  - `TestSpecNewBranchesFromOriginDev`: origin's `dev` is one commit ahead of local `dev` → the new branch's
    parent is origin's commit, and `git config branch.docs/NNN-x.merge` is unset;
  - `TestSpecNewStopsWhenDevAhead`: local `dev` has a commit not on origin → exit 2, the message names the
    count, and nothing changed (branch, HEAD, status);
  - `TestSpecNewStopsWhenFetchFails`: the origin URL points nowhere → exit 2, nothing changed;
  - `TestSpecNewStopsWithoutOriginDev`: origin has no `dev` → exit 2.
  The existing tests with no remote keep passing (local `dev`), and so do the remote-numbering tests.
- Code: with an `origin` remote, run `git fetch origin dev`; refuse on fetch failure, on a missing
  `refs/remotes/origin/dev`, or when `git rev-list --count origin/dev..dev` is above 0; branch with
  `git switch --no-track -c <branch> origin/dev`.
- Prove it: `go test ./cmd/pal-harness/` and `go vet ./...` pass.
- Commits: `Pin spec new from origin/dev in failing tests`, then `Branch spec new from origin/dev`.
