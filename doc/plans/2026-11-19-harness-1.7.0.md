# pal-harness 1.7.0: plan

**Design:** `doc/specs/2026-11-19-harness-1.7.0-design.md` (approved 2026-11-19).
**Branch:** `feature/harness-1.7.0` from `origin/dev`, one PR into `dev`.

## Summary

1. Tasks: (1) failing tests for the rules, the template and the workflows; (2) the `fingerprint`
   package and command; (3) the two reusable workflows and `templates/ci.yml`; (4) the rule text;
   (5) version, README and CHANGELOG; (6) the Pal Center capture; (7) the PR.
2. Repo: pal-harness only. No project's pin changes.
3. Approach: inline. One repo, one small Go package, two workflows and text.
4. Proof: `go vet ./...` and `go test ./...` (what `ci.yml` runs), with `go test -coverprofile`
   holding the 80% gate. Local runs set `GOFLAGS=-p=1 GOMEMLIMIT=2GiB`.
5. Risks: the reusable workflows only run for real from the `v1.7.0` tag, in a project's CI. The
   tests check their shape (permissions, inputs through `env`, version validated, the template's
   wiring); the first adoption quick fix (Pal Center) is their live test.

## Gate dry-runs

No task uses a grep or lint gate beyond the repo's own vet and tests; the new tests run red first.

## Deletes and locks

none: no task deletes anything or takes a lock.

## Tasks

### Task 1: the failing tests

- Files: `content_test.go`: `TestHarness170Rules`, built like `TestHarness160Rules`, phrases per
  design change (1, 2, 4, 5, 6) in each file the design names; `TestContentComplete` lists
  `content/templates/ci.yml`. `workflows_test.go`: `TestCIGateWorkflowsHardened` (both reusable
  workflows: `workflow_call`, the right permissions, no `${{` in `run:`, `ci-gate.yml` validates
  `inputs.version` before `pal-harness@v`) and `TestCITemplateWiring` (the template parses, has the
  concurrency group with `cancel-in-progress: true`, calls both workflows at `@v<Version>` with
  `version: <Version>`, its example job's `if` reads `needs.gate.outputs.decisions || '{}'` under
  `!cancelled()`, and `mark` passes `toJSON(needs)` with `contents: write`).
- Prove it: `go test -run 'TestHarness170Rules|TestContentComplete|TestCIGate|TestCITemplate' .`
  fails (red).
- Commit: "Pin the 1.7.0 rules in a failing test".

### Task 2: `pal-harness fingerprint`

- Files: `fingerprint/fingerprint.go` (`ParseSpec`, `Compute` with an injected object-id lookup;
  `GitLookup(dir, rev)` running `git rev-parse --verify --quiet <rev>:<path>`),
  `fingerprint/fingerprint_test.go`; `cmd/pal-harness/fingerprint_cmd.go` (`runFingerprint`:
  `--rev` default `HEAD`, repeatable `--with`, `--dir` default `.`, one spec file or `-` for stdin)
  and `fingerprint_cmd_test.go`; the usage text and `run` switch in `main.go`.
- Test first: spec parsing (comments, blank lines, a duplicate job, a bad job name, no paths, an
  absolute or `..` path); the hash matches the documented form; against a temporary git repo, the
  Pal Center cases: a docs-only change leaves both jobs alone, a same-tree commit keeps both, a change
  under one job's path changes only it, a `--with` file change changes all, a new or deleted file
  under a path changes it, a missing path hashes as `missing`; the command's usage errors, stdin
  input and a non-repo directory (exit 2).
- Prove it: `go test ./fingerprint ./cmd/...` red, then green; `go vet ./...`.
- Commit: "Add pal-harness fingerprint".

### Task 3: the reusable workflows and the caller template

- Files: `.github/workflows/ci-gate.yml`, `.github/workflows/ci-mark.yml`, `content/templates/ci.yml`.
- `ci-gate.yml`: inputs `version`, `jobs`, `shared`; validates the version; checkout; setup-go
  (`cache: false`); writes the spec from `env`, runs `pal-harness@v${VERSION} fingerprint --with
  .github/workflows/ci.yml [--with <shared>...]`, looks up each ref with `gh api`, writes
  `decisions` and `fingerprints` JSON (with `jq`) and the run summary.
- `ci-mark.yml`: inputs `fingerprints`, `results`; for each job with `success` creates the ref, or
  finds it existing, or warns.
- Prove it: Task 1's workflow tests green; `go test ./...`.
- Commit: "Add the reusable CI gate workflows".
