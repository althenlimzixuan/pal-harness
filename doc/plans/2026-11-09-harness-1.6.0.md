# pal-harness 1.6.0: plan

**Design:** `doc/specs/2026-11-09-harness-1.6.0-design.md` (approved 2026-11-09).
**Branch:** `feature/harness-1.6.0` from `origin/dev`, one PR into `dev`.

## Summary

1. Tasks: (1) a failing `TestHarness160Rules`; (2) the `mem` package and command; (3) the `adb`
   package and command; (4) the screenshot template and the rule text; (5) version, README and
   CHANGELOG; (6) the Pal Center capture; (7) the PR.
2. Repo: pal-harness only. No project's pin changes.
3. Approach: inline. One repo, two small Go packages and text.
4. Proof: `go vet ./...` and `go test ./...` (the commands `ci.yml` runs), and
   `go test -coverprofile` holding the 80% gate. Local runs set `GOFLAGS=-p=1 GOMEMLIMIT=2GiB`.
5. Risks: the two commands touch the OS (`GlobalMemoryStatusEx`, `/proc/meminfo`, `adb`). The logic
   sits behind a reader and a runner that tests fake; the OS reads are a few lines each.

## Gate dry-runs

No task uses a grep or lint gate beyond the repo's own vet and tests; `TestHarness160Rules` is a
test, run red first.

- Commit: "Pin the 1.6.0 rules in a failing test".

### Task 2: `pal-harness mem`

- Files: `mem/mem.go` (`ParseSize`, `Check` with an injected reader, sleeper and clock),
  `mem/read_windows.go` (`GlobalMemoryStatusEx`, `ullAvailPhys`), `mem/read_linux.go`
  (`MemAvailable` in `/proc/meminfo`), `mem/read_other.go` (unsupported → error); `mem/mem_test.go`;
  `runMem` in `cmd/pal-harness/main.go` with `--min` (default 2GiB), `--wait` (default 0),
  `--every` (default 30s); `main_test.go` cases for usage and exit codes.
- Test first: `mem/mem_test.go` — sizes (`2GiB`, `512MiB`, `1.5GiB`, bad input), enough at once,
  short then enough within the wait, still short after the wait, a reader error; parsing of a sample
  `/proc/meminfo`.
- Exit codes: 0 enough; 1 still short; 2 usage or unreadable.
- Prove it: `go test ./mem ./cmd/...` red, then green; `go vet ./...`.
- Commit: "Add pal-harness mem".

### Task 3: `pal-harness adb`

- Files: `adb/adb.go` (`ParseDevices` for `doc/devices.yaml`, `Up` with an injected `Runner`,
  parsing of `adb devices` and `adb mdns services`), `adb/adb_test.go`; `runAdb` in `main.go` (reads
  `<dir>/doc/devices.yaml`, finds `adb` on PATH, prints one line per device and the pairing message);
  `main_test.go` cases.
- Test first: a device already listed; reconnect at the saved address; saved address fails and mDNS
  finds a new port (matched by serial, then by IP), with the new address printed; nothing works → not
  ready with the pairing message; the reverse ports set on each ready device; a failed reverse; no
  `disconnect` or `kill-server` ever run; bad or empty `devices.yaml`.
- Exit codes: 0 every device ready; 1 one not ready; 2 usage, no `doc/devices.yaml` or no `adb`.
- Prove it: `go test ./adb ./cmd/...` red, then green; `go vet ./...`.
- Commit: "Add pal-harness adb".
